# 0.7.0 — Un processus Claude Code par agent, qui vit entre les tours

## Ce que ça fait

- Aujourd'hui, un tour = un `query()` (F-59) : un processus Claude Code par
  tour, qui meurt à la fin du tour, et avec lui tout ce qu'il surveillait ou
  avait lancé en arrière-plan. C'est ce qui arrêtait les surveillances de
  l'agent à la fin de chaque tour.
- Cible : **un processus par agent**, lancé au premier message, gardé entre
  les tours ; les messages suivants lui sont transmis (`streamInput`). Une
  tâche de fond survit donc au tour qui l'a lancée, et sa notification
  arrive dans la session, où l'agent la lit au tour suivant.
- Le processus s'arrête : à *Nouvelle session*, *Retirer*, à la fermeture de
  l'appli (I-19 : on demande d'abord, on tue après 5 s), et après une erreur
  du processus (le suivant en relance un).
- Vu de l'utilisateur : rien ne change dans le fil ni dans les menus. Changer
  de mode ou de modèle pendant un tour continue de s'appliquer aussitôt
  (F-57, `setPermissionMode` / `setModel`).

## Ce que ça ne doit pas faire

- Envoyer un message à un agent au travail (I-25) : inchangé, le processus
  persistant ne le permet pas davantage. → invariant existant
- Laisser un processus orphelin à la fermeture : chaque processus vivant est
  arrêté comme aujourd'hui (I-19). → invariant existant, à rejouer sur le
  nouveau runtime
- Mélanger les sessions : un message part toujours au processus **de cet
  agent**, dans sa session (I-22). → invariant existant
- Perdre la consigne `<audio>` ou les réglages entre deux tours (I-24, F-58).
  → variant suffit
- Un processus en erreur qui bloque l'agent : le tour suivant en relance un,
  comme aujourd'hui (I-29). → variant suffit

## Ce que ça touche

- `main/core/agents/runtime.ts` : la boucle d'un tour, l'interruption, la
  fermeture ; `options.ts` (`prompt`, aujourd'hui un générateur d'un seul
  message) ; `sessions.ts` (la session est reprise par `resume` : avec un
  processus persistant, seul le premier tour la crée).
- `main/app/controllers/agents.ts`, `conversation.ts` : *Nouvelle session*,
  *Retirer*, la sonde (F-72).
- `main/core/agents/tests/invariants/` : I-19, I-25 rejoués.
- SPEC F-59, I-19 ; § 1.

## Forme

```
main/helpers/async-queue.ts   createQueue<T>() → { push, close, [asyncIterator] }
                              pur ; l'entrée d'un processus, ouverte tant qu'il vit
                              · utilisé par : core/agents (runtime)
main/core/agents/options.ts   userMessage(message) → SdkMessage (ex-prompt())
                              launchKey(agent, command, instructions) → string :
                              ce qu'un processus vivant ne peut pas changer
                              (dossier, effort, consigne, commande) ; s'il change,
                              le processus est relancé. Mode et modèle : à chaud.
main/core/agents/runtime.ts   Runtime { process: Proc | null ; turn: Turn | null ;
                              hooks ; … }
                              Proc { query, input: AsyncQueue, abort, key,
                                     sessionId, ended: Promise<void> }
                              Turn { asked, since, resolve, permissionFailures,
                                     interrupted }
                              send(agent, message, hooks) :
                                busy → 'busy' ; launcher → 'notInstalled' ;
                                process d'une autre clé → close() ;
                                pas de process → start() : query({ prompt: queue,
                                  options: queryOptions + abortController +
                                  canUseTool }), puis loop() en tâche de fond ;
                                process existant → setPermissionMode(mode),
                                  setModel(model) ;
                                turn = { … } ; input.push(userMessage) ;
                                résout à la fin DU tour (result), comme avant.
                              loop(r) : for await m of query —
                                init → onSession ; assistant/user → onProgress ;
                                assistant sans tour en cours → tour commencé
                                par l'agent lui-même (notification de tâche) :
                                même fin de tour, réponse non lue ;
                                tool_result « permission request failed » →
                                compté ; result → endTurn.
                                Fin de boucle (processus mort, tué) : process =
                                null ; un tour en cours finit en 'interrupted'
                                si abort, sinon en erreur.
                              interrupt(id) : query.interrupt() ; après
                                INTERRUPT_GRACE_MS, si le MÊME tour court
                                encore : abort (le processus meurt, le suivant
                                en relance un).
                              close(id) → Promise : interrupt si un tour
                                court, input.close() (Claude Code sort de
                                lui-même, comme la sonde) ; après le délai,
                                abort. L'état de l'agent est gardé.
                              forget(id) : close + oubli de l'état.
                              stop() : close de tous ; résout quand tous sont
                                sortis (ou tués).
                              active() → nombre de processus vivants.
                              probe : le processus de l'agent s'il existe,
                                sinon la sonde temporaire (inchangée).
                              setMode / setModel : sur le processus, tour en
                                cours ou non.
main/app/controllers          resumeSession → agents.close(id) après la
                              session changée ; lifecycle before-quit attend
                              stop() dès qu'un processus vit (active()).
```

## Pistes pour plus tard

- Garder le processus après la fermeture de l'appli (une tâche de fond
  survivrait au redémarrage) : non, l'appli reste maître de ses processus.
