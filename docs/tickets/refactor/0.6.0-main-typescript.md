# 0.6.0 — Le processus principal en TypeScript

## Ce que ça fait

Rien de neuf pour l'utilisateur. Le processus principal d'Electron
(`src/*.js`, ~3 000 lignes dont `main.js` ~1 500) et les trois ponts
(`*preload.js`) sont réécrits en TypeScript. Ils sont découpés en modules selon
le rangement des pages (`app`, `core`, `helpers`, `technicals`, un barrel par
module), avec les invariants du principal enfin testés. Le comportement reste
celui de `SPEC.md` (0.4.0) et de la note Obsidian « Whisper 0.4.0 - État des
lieux et invariants ».

Construit par Vite (`out/main/`, CommonJS ; le SDK Claude reste un `import()`
dynamique). Les scripts lancés par l'appli (`windows-helper.ps1`,
`pocket-helper.py`) passent de `src/` à `resources/scripts/`, livrés hors de
l'archive comme les binaires.

Un écart voulu : le contrôle de l'expéditeur (I-20) s'applique à **tous** les
canaux, plus seulement à `agent:*` et `conv:*`. Chaque fenêtre n'est écoutée
que sur ses propres canaux ; un message venu d'une autre est ignoré.

## Ce que ça ne doit pas faire

- Écouter un canal sans contrôler l'expéditeur, ou ailleurs que par
  `technicals/ipc` (I-20). → invariant
- Ouvrir côté principal un canal que le pont n'expose pas, ou l'inverse (I-3).
  → invariant
- Laisser un retour à la ligne dans une transcription (I-4). → invariant
- Rendre le presse-papiers après un collage raté ou désactivé, ne pas le rendre
  après un collage réussi, simuler une touche collage désactivé (I-5, I-6).
  → invariant
- Laisser coupé ce que l'appli a coupé ; rétablir ce qu'elle n'a pas coupé ;
  couper ses propres flux ou autre chose que la capture de Discord (I-11,
  I-12). → invariant
- Accorder par « Toujours autoriser » autre chose que des règles pour la
  session (I-14) ; répondre à une autre demande que la tête de file (I-15) ;
  perdre une demande (I-17). → invariant
- Tuer Claude Code avant de lui avoir demandé d'arrêter, ou le laisser tourner
  au-delà du délai (I-19). → invariant
- Montrer une demande d'autorisation raccourcie ou coupée sans le dire
  (I-13). → invariant
- Démarrer avec un agent sélectionné (I-8) ; ajouter un dossier sans la
  question de confiance (I-23). → invariant
- Mettre la consigne `<audio>` ailleurs que dans le prompt système de nos
  sessions (I-24). → invariant
- Accorder une autre permission que le micro à nos pages ; ouvrir autre chose
  qu'une adresse http(s) ; ouvrir un fichier joint (I-9, I-21). → invariant
- Lancer un programme par un shell (I-27). → invariant (analyse du code)
- Bloquer la dictée ou un agent parce qu'un service annexe échoue (I-29). →
  invariant
- Changer quoi que ce soit de visible ou de fonctionnel. → scénarios S-1 à
  S-41 ; bancs de comparaison : pages (`tests/front-diff`) et appli réelle
  (`tests/main-diff`, contre la 0.5.0).

## Où ça casse

- `main.js` tient tout son état dans une seule fermeture (fenêtres, vue du
  panneau, dictée en attente…). Découpé, cet état vit dans `app/state.ts`, seul
  objet partagé entre les contrôleurs.
- Les scripts PowerShell et Python étaient sortis de l'archive par
  `asarUnpack` et trouvés à côté de `paths.js`. Le code étant maintenant
  regroupé dans `out/main/`, ils vivent dans `resources/scripts/` (paquet :
  `process.resourcesPath/scripts`).
- Le SDK Claude est un module ES : chargé par `import()`, jamais `require`.

## Ce que ça touche

`src/` entier hors des pages, `package.json` (`main`, scripts, fichiers du
paquet), `tsconfig*.json`, configurations Vite et Vitest, CI (chemin du script
PowerShell), `tests/invariants/bridges.test.ts` (les ponts sont en TypeScript,
le principal n'écoute que par `technicals/ipc`), `tests/front-diff` (ponts
construits), `tests/main-diff` (nouveau), `AGENTS.md`, `SPEC.md`, `README.md`.

## Forme

```
src/shared/bridge/        contrat des ponts (types) · utilisé par les pages, les ponts, le principal
src/preload/              icon.ts, bubble.ts, panel.ts : chaque pont, typé par le contrat
src/main/
  index.ts                l'entrée : app/lifecycle
  app/                    ce qui connaît Electron et les fenêtres
    state.ts              l'état partagé : fenêtres, vue du panneau, dernière dictée…
    windows/              icon-window, bubble-window, panel-window : créer, placer, montrer
    controllers/          dictation, speech, agents, conversation : les orchestrations
    menus/                main-menu, agent-menus (robot, « + », trombone)
    ipc/                  icon-, bubble-, panel-handlers : une table de gestionnaires par fenêtre
    lifecycle.ts          démarrage, sortie
  core/                   le métier · ne connaît ni Electron ni app/
    config/               réglages, défauts, démarrage (aucun agent sélectionné), dossiers
                          favoris et couleurs, confiance
    dictation/            transcription d'une ligne, destination du texte, collage et
                          presse-papiers (outils injectés)
    sound/                createMuter : couper, et rétablir ce qu'on a coupé (outils injectés)
    agents/               createAgentRuntime : tours, file d'autorisations, interruption,
                          sonde (SDK et lancement injectés) ; réponse et résumé audio ;
                          transcription relue ; sessions d'un dossier
    conversation/         ce que montre le panneau : actions, demande d'autorisation,
                          pièces jointes (composer, relire, préparer)
    guards/               permissions des pages, liens, fichiers montrés
  helpers/                command-line, lang, text · pur
  technicals/             ce que fournit la plateforme · ne dépend que de lui-même et de helpers
    ipc/                  listenFrom : une fenêtre, ses canaux, l'expéditeur contrôlé
    paths/                which, scriptPath, binDir
    whisper-cli/          localiser, lancer, WAV
    paste/                Ctrl+V simulé (wtype, ydotool, xdotool ; assistant Windows)
    windows-helper/       l'assistant PowerShell permanent
    pipewire/             flux, volume, coupure (wpctl)
    clipboard/            photographier, rendre, écrire
    selection/            lire la sélection ou le presse-papiers (wl-paste, Ctrl+C sous Windows)
    pocket-tts/           installation, processus Python, lecture par morceaux
    claude/               lancement de Claude Code, chargement du SDK
    journal/              journal des agents, rotation
    images/               réduire une image, aperçu
    config-file/          lire et écrire config.json
resources/scripts/        windows-helper.ps1, pocket-helper.py
```

Les tests vivent dans leur module (`tests/invariants/`, protégés ;
`tests/variants/`). `tests/invariants/` à la racine : ce qui traverse les
modules (ponts, absence de shell). `tests/main-diff/` : le banc du principal,
l'appli réelle comparée à une version publiée.

## Pistes pour plus tard

- Le banc du principal ne couvre pas ce qui demande Claude Code (tours,
  autorisations réelles) ni les coupures du son : ces parties sont tenues par
  leurs invariants (SDK et outils factices) et par les scénarios manuels.
