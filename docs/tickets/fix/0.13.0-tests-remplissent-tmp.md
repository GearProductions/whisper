# 0.13.0 — Les tests remplissent /tmp

## Ce que ça fait

Envoyer un message dans la conversation principale ne donnait plus rien : le
message part, la zone de discussion s'efface, l'agent revient inactif — dans
la version de dev comme dans l'AppImage publiée. Claude Code lui-même ne
lançait plus aucune commande (`ENOSPC`). `/tmp` (tmpfs) avait épuisé ses
inodes (1 048 576 sur 1 048 576), l'espace disque restant libre.

La cause : une vingtaine de fichiers de tests du principal créent leur profil
et leur dépôt git d'essai par `mkdtemp(os.tmpdir())` à chaque cas et ne les
effacent jamais. Un dépôt, c'est un millier de fichiers ; après des milliers
de lancements (les agents relancent les tests à chaque étape), environ 12 000
dossiers `whisper-*-XXXXXX` remplissaient `/tmp`.

Le correctif : `tests/tmp-dir.ts`, un `globalSetup` de vitest, crée un
dossier `whisper-tests-XXXXXX` par lancement, y fait pointer `os.tmpdir()`
pour tous les tests (`TMPDIR`, et `TMP`/`TEMP` sous Windows), et l'efface à
la fin. Un seul endroit pour tous les fichiers, protégés compris, sans les
toucher.

## Ce que ça ne doit pas faire

- Toucher un test protégé (`tests/invariants/`). → vu en review
- Changer ce qu'un test vérifie ou le comportement de l'appli : seul le
  dossier temporaire des tests change. → vu en review
- Laisser un dossier dans le `/tmp` du système après `npm test`. → vu en
  review (vérifié à la main : 1900 cas, aucun dossier ajouté)

## Ce que ça touche

- `tests/tmp-dir.ts` (nouveau)
- `vitest.config.mts` (`globalSetup`)

Hors de ce ticket : `npm run test:main-diff` (`tests/main-diff/run.mjs`,
hors vitest) laisse encore son profil quand un relevé échoue, un dossier par
échec.
