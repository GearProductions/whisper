# 0.16.0 — Les actions lisent les artefacts du projet

Branche `fix/0.16.0-action-note-access-artefact`.

## Ce que ça fait

- Symptôme (conversation GT Plugin, 2026-11-24) : l'orchestrateur lance *Rédiger la note* de G2-6823 en lui passant le chemin d'un artefact de découpage (`…/vibecoder-artifacts/b91de42c25b51f42/G2-6818-plan-decoupage-pr.md`). La course finit sur « Appels refusés : Read « …/G2-6818-plan-decoupage-pr.md » » ; la note est écrite sans l'annexe, et l'orchestrateur doit recoller les passages utiles dans la demande.
- Cause : le contrôle des outils de fichiers d'une course (`fileDecision`, crochet PreToolUse) ne laisse lire que le projet, les sorties de l'agent et le plugin de VibeCoder ; le dossier d'artefacts du projet n'est donné qu'à la conversation (F-115 : « le dossier des artefacts du projet reste à la conversation »).
- Attendu : **toute course** (et ses sous-agents) peut **lire** le dossier d'artefacts de son projet : `Read`, `Glob`, `Grep` sous `vibecoder-artifacts/<clé>/` passent, comme pour le plugin (une seule règle dans le contrôle, sans liste d'actions à tenir ; un dossier en lecture seule ajoute peu de risque). Un artefact donné en contexte (son chemin dans la demande, ou cité dans la note) est donc lu.
- **Lecture seule** : une course n'écrit toujours pas dans le dossier d'artefacts (c'est le besoin constaté ; écrire un artefact reste à la conversation, par le skill *artefact*).
- Worktree : rien de particulier. La clé du dossier d'artefacts est le dossier git commun (`projectKey`) : un worktree et le dépôt principal ont le même dossier d'artefacts (F-95), une course lancée depuis un worktree lit donc les artefacts rangés par le robot du dépôt principal.
- Le skill *note* compte un artefact que la demande désigne parmi ses sources : chaque ligne vient de la demande, du code, d'une note existante ou d'un artefact que la demande désigne (sinon l'accès sert peu).
- SPEC : F-115 (le dossier d'artefacts du projet en lecture) et I-57 (« le plugin et le dossier d'artefacts du projet en lecture ») ; README : les droits des actions.

## Ce que ça ne doit pas faire

- Écrire dans le dossier d'artefacts du projet depuis une course ou un de ses sous-agents → invariant (déjà tenu par un test protégé)
- Lire, par le dossier d'artefacts, un fichier hors de lui, du projet et des sorties (`../`, un lien posé dans le dossier d'artefacts qui mène au dehors, ou le dossier d'artefacts lui-même devenu un lien : alors aucun dossier d'artefacts pour la course) → invariant (cas protégés ajoutés)
- Lire le dossier d'artefacts d'un autre projet (une autre clé) → invariant (cas protégé ajouté)
- Changer les dossiers de travail donnés au processus d'une course (`additionalDirectories` : le projet et les sorties seuls) → invariant (déjà tenu par un test protégé)
- Changer la conversation de l'agent : elle garde le dossier d'artefacts en dossier de travail, comme aujourd'hui → variant suffit

## Ce que ça touche

- `src/main/core/vibecoder/bounds.ts` : `Bounds` (`project`, `out`, `plugin`, `reads`) et `fileDecision` (la lecture : projet, sorties, plugin) ; son en-tête.
- `src/main/app/controllers/runs.ts` : `runRights` (les `bounds` de la course) ; `startRun` (`dirs: [vibeOutDir(agent.id)]`, inchangé, son commentaire à revoir).
- `src/main/app/controllers/artifacts.ts` : `projectArtifactsPath` (le dossier d'un projet, sans le créer).
- `src/main/app/controllers/agents.ts` : la conversation reçoit `projectArtifactsDir(agent.dir)` (inchangé).
- `src/main/app/controllers/tests/invariants/run-rights.test.ts` : protégé ; « le dossier des artefacts du projet : refusé » (une écriture) et « les dossiers de travail donnés au processus » restent tels quels ; les nouveaux cas (sortie par `../` ou par un lien, autre projet) s'y ajoutent, avec l'accord de l'utilisateur.
- `src/main/core/vibecoder/tests/variants/bounds.test.ts` : les cas de `fileDecision`.
- `resources/vibecoder/plugin/skills/note/SKILL.md` : la règle « every line comes from the request, the code or an existing note ».
- `SPEC.md` : F-115 (« ses sorties pour seul dossier en plus »), I-57 (« ne lisent ni n'écrivent hors du projet et des sorties de l'agent (le plugin en lecture) »).
- `README.md` : les droits des actions (« Ses outils de fichiers lisent dans le projet, les sorties de l'agent et le plugin de VibeCoder… »).

## Forme

**Une borne de plus, en lecture.** Le contrôle reçoit le chemin réel du
dossier d'artefacts du projet, comme celui du plugin : une lecture dessous
passe, une écriture n'y est jamais permise (la règle d'écriture ne change
pas : le projet et les sorties). Rien d'autre ne bouge : ni les dossiers de
travail du processus, ni la conversation.

**Le lien jugé à la source.** `runRights` ne passe le dossier que s'il existe
et n'est pas un lien (`lstat`) ; sinon aucun pour la course. Un lien posé
dedans, ou un `../`, se résout hors de lui par `real` et reste refusé, comme
le dossier d'un autre projet (une autre clé).

```
src/main/core/vibecoder/bounds.ts  (repris) le dossier d'artefacts lu
    Bounds gagne artifacts, facultatif : le chemin réel du dossier
    d'artefacts du projet ; absent, aucun pour la course
    fileDecision : une lecture (Read, Glob, Grep) sous artifacts passe ;
    une écriture dessous refusée, comme hors du projet ; le motif d'un
    Glob jugé comme avant
    ne connaît pas : la clé d'un projet, où vivent ses artefacts, le disque
    (le chemin réel et real sont passés)
    utilisé par : app/controllers (runs : runRights) ; en-tête retouché
    variants : src/main/core/vibecoder/tests/variants/bounds.test.ts
    - Read, Glob, Grep d'un artefact sous artifacts : passe
    - Write, Edit d'un artefact sous artifacts : refusé
    - artifacts absent : un Read sous ce dossier refusé, comme avant
    - un chemin sous artifacts qui en sort par ../ : refusé
    - un lien dans artifacts vers /etc : refusé
    - un dossier voisin (une autre clé) : refusé

src/main/app/controllers/runs.ts  (repris) les bornes d'une course
    runRights passe à bounds le chemin réel de projectArtifactsPath(agent.dir)
    s'il est un dossier et pas un lien, sinon rien ; sans le créer
    startRun : dirs inchangé (les sorties seules), son commentaire dit
    que le dossier d'artefacts reste lisible par le contrôle
    ne connaît pas : la décision du contrôle (core/vibecoder bounds)
    utilisé par : inchangé ; en-tête retouché, et celui de
    controllers/artifacts (runs parmi ses utilisateurs)
    variants : src/main/app/controllers/tests/variants/runs.test.ts
    - un artefact du projet : Read passe, Write refusé
    - un artefact rangé depuis le dépôt principal, la course dans un
      worktree : Read passe
    - aucun dossier d'artefacts encore : la course part, rien n'est créé
    - les dossiers de travail : toujours les sorties seules (cas existant)

resources/vibecoder/plugin/skills/note/SKILL.md  (repris) l'artefact parmi les sources
    la règle « every line comes from » compte aussi un artefact que la
    demande désigne (son chemin dans la demande)
    ne connaît pas : l'appli (texte de skill)
    utilisé par : l'action Rédiger la note
    variants : aucun, du texte de skill

SPEC.md + README.md  (repris) les droits des actions
    SPEC : F-115, le dossier d'artefacts du projet en lecture pour une
    course et ses sous-agents ; I-57, « le plugin et le dossier
    d'artefacts du projet en lecture »
    README : les outils de fichiers d'une action lisent aussi le dossier
    d'artefacts du projet, sans y écrire
    variants : aucun, de la doc
```
