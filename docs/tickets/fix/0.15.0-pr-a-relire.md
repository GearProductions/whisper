# 0.15.0 — « À relire » à jour tout de suite

Branche `fix/0.15.0-pr-a-relire`, créée depuis `master`. PR express (un correctif rapide, demandé par l'utilisateur).

## Le bug

Dans la vue des branches, après *Me demander en relecture* sur une PR, elle ne paraît pas dans *À relire*, même après *Actualiser*, alors que GitHub l'a bien enregistrée. Deux causes :
- *À relire* venait seulement de la recherche GitHub `review-requested:@me`, dont l'index a quelques minutes de retard : relue juste après le geste, la liste répondait l'ancien état.
- *Actualiser* ne faisait qu'un `git fetch` : il ne relisait pas les listes de PR.

## La correction

- *À relire* = la recherche (elle voit aussi les demandes faites à une équipe) plus les PR de la liste entière dont les demandes de relecture (`reviewRequests`, lues directement, à jour) nomment mon identifiant. `openPrs` ne lance toujours que `gh pr list` (invariant I-39) ; l'identifiant est lu par l'appelant (`gh api user --jq .login`, la seule forme permise).
- *Actualiser* relit aussi les listes de PR.

## Ce que ça ne doit pas faire

- Lancer gh autrement qu'en lecture (I-39, protégé) → invariant (existant)
- Perdre une PR que seule la recherche voit (une demande faite à une équipe) → variant suffit
