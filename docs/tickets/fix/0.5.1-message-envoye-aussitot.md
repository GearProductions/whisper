# 0.5.1 — Le message envoyé s'affiche aussitôt

## Ce que ça fait

- Entrée (ou dictée envoyée directement) : votre message apparaît dans le fil
  en même temps que « … travaille », pas une ou plusieurs secondes après.
  Aujourd'hui le fil est relu dans la transcription de Claude Code, où le
  message n'est écrit qu'une fois Claude Code lancé ; l'état « au travail »,
  lui, part tout de suite.
- Tant que la transcription ne contient pas le message, le principal
  l'ajoute au fil tel qu'il a été envoyé (texte, sélection, fichiers,
  images) ; dès qu'elle le contient, c'est elle qui fait foi.

## Ce que ça ne doit pas faire

- Afficher le message deux fois (transcription + message en attente). →
  variant
- Garder un message en attente après la fin du tour (tour en échec avant
  d'écrire la transcription : le message disparaît, l'erreur s'affiche comme
  aujourd'hui). → variant
- Se placer avant la sortie d'une commande locale reprise de la dernière
  réponse (`/context`). → variant

## Forme

```
core/agents/runtime.ts        sent(id) : le message du tour en cours ({ text, images }),
                              null hors tour. À part de state(id), qui part à l'icône :
                              les images n'ont rien à y faire.
core/conversation             withSent(thread, sent, since) → Thread : ajoute le message
                              en attente s'il n'y a pas, depuis `since`, de message
                              « user » dans la transcription. Pur.
                              Utilisé par : app/controllers/conversation.
```

## Ce que ça touche

- `app/controllers/conversation.ts` : `refreshConversation` passe le fil
  par `withSent` (après la reprise de la sortie de commande), avant la mise
  en forme des messages.
- SPEC F-66 : « votre message s'affiche dès l'envoi ».
