# 0.15.0 — Des droits d'actions utilisables sur tous les projets

Urgent : à livrer avant la release candidate 0.15.0. Remplace T-34 de la liste
des tickets.

## Ce que ça fait

**Le problème.** Les droits d'une course (PR #88, note
`feat/0.15.0-courses-droits`) tiennent deux choses :
- les bornes, tenues par l'appli (le crochet `PreToolUse`) : rien lu ni écrit
  hors du projet, des sorties de l'agent et du plugin ; aucun fichier qui donne
  des droits (`AGENTS.md`, `package.json`, `.git/`, `.husky/`, les skills, les
  réglages) ; un mode qui ne demande jamais, jamais le mode *Auto*. Ça marche :
  on le garde, inchangé ;
- une liste blanche de commandes : la liste du skill, plus les commandes de
  test, de typage et de lint reconnues à leur nom dans la section « Commandes »
  d'`AGENTS.md`. Elle bloque tout : pas de `cargo build` (son nom ne dit pas
  test), pas de `cd frontend && npm test` (enchaîné), pas de `npx vitest` si
  `AGENTS.md` écrit `npm test`, pas de `git -C`. Vu le 12 novembre sur
  workflows-tester, et dans ce dépôt : *Appliquer la revue*, *Replier les
  fixups* et *Ouvrir la PR* ont échoué à leur travail. Une liste blanche ne
  peut pas suivre la diversité des projets.

**La voie simple** (décidé le 12 novembre : le but de départ était seulement de ne
plus faire tourner les actions en mode *Auto* ; une protection codée en dur qui
bloque tout fait échouer les actions et coûte des tokens en reprises ; un
analyseur de commandes maison, posé par une première Forme, a été abandonné).
- Les bornes de fichiers restent, inchangées : le contrôle de l'appli
  (`PreToolUse`) refuse toute lecture ou écriture par les outils de fichiers hors
  du projet, des sorties de l'agent et du plugin, et toute écriture d'un fichier
  qui donne des droits ; jamais le mode *Auto*, une course ne demande jamais
  (PR #88).
- `Bash` passe en entier pour une course : plus de liste blanche de commandes.
  La règle qui reconnaissait les commandes du projet à leur nom dans `AGENTS.md`
  disparaît ; `cargo build && cargo test`, `cd frontend && npm test`,
  `npx vitest`, `git -C …` passent.
- Une courte liste de refus, donnée à Claude Code au départ de chaque course
  (ses règles de refus, qu'il applique lui-même à chaque morceau d'un
  enchaînement) : ce qui part à l'extérieur (`git push`, `gh`, `curl`, `wget`),
  ce qui change les dépendances (`npm install`, `npm i`, `npm add`, `yarn add`,
  `pnpm add`, `cargo add`, `cargo install`, `pip install`), ce qui détruit
  (`git reset --hard`, `git clean`, `rm -rf`, `sudo`), les commandes git qui
  écrivent (`git add`, `git commit`, `git rebase`, `git checkout`, `git switch`,
  `git stash`, `git merge`, `git tag`, `git branch -D`, `git config`), le
  système (`kill`, `pkill`, `systemctl`, `podman`, `distrobox`) et la CLI de
  VibeCoder. Une vingtaine de lignes, dans un seul fichier, faciles à relire.
- Le skill ouvre ce qui est son travail : une commande de cette liste qu'il
  nomme dans son `allowed-tools` lui est retirée des refus (*Créer la PR* :
  `git push --force-with-lease`, `gh pr create`, `gh pr view` ; *Commiter* :
  `git add`, `git commit` ; *Replier les fixups* : `git rebase` ; *Lancer les
  vérifications* : la CLI pour la ponytail review ; etc.). Les autres outils du
  skill (`Read`, `Write`, `Edit`, `Agent`…) restent listés comme aujourd'hui.
- Le reste en consignes : la consigne d'outils commune (PR #89) est allégée —
  plus d'« un appel par commande » ; elle dit de rester dans son travail, de lire
  par `Read` quand c'est possible, et qu'une commande refusée est à contourner
  autrement ou à signaler, sans la répéter.
- Le compromis, accepté : une forme tordue que Claude Code ne découpe pas
  (`timeout 60 git push`, `bash -c "…"`) peut passer ; les agents et les skills
  sont les nôtres, et le vrai rempart reste les bornes de fichiers. Les refus
  restent cités en tête de la réponse, sans faire échouer la course (PR #89).

**Le dossier temporaire d'une course** (décidé le 13 novembre : le 12, `/tmp`, en mémoire, s'est rempli — 30 Go — au point de bloquer les commandes et de faire échouer des tests ; le suspect est une commande de fond d'une course qui écrit sans fin dans sa sortie, et qui survit à la course).
- Chaque course reçoit son propre dossier temporaire (`CLAUDE_CODE_TMPDIR`), sous les sorties de l'agent, effacé à la fin de la course, quelle qu'elle soit (finie, en échec, arrêtée). Une fuite ne survit pas à la course, et on sait laquelle a débordé.
- Une borne : si ce dossier dépasse 1 Go pendant la course (un réglage, le chiffre n'est pas l'invariant), l'appli arrête la course, une ligne en tête de sa réponse le dit.
- Les tests ne laissent plus leurs dossiers temporaires (`whisper-agents-…` : 1 138 dossiers trouvés).

## Ce que ça ne doit pas faire

- Laisser passer, pour une course, une commande de la liste de refus que son skill n'ouvre pas, quel que soit le mode de l'agent principal → invariant (I-57 revu, famille « permissions » : la liste de refus donnée au SDK ; retouche du test protégé `run-rights.test.ts` décidée par ce ticket, signalée dans la PR)
- Relâcher les bornes : lire ou écrire hors du projet, des sorties et du plugin par les outils de fichiers, écrire un fichier qui donne des droits, un mode qui demande, le mode *Auto* ou le contournement des autorisations → invariant (I-57, inchangé)
- Refuser une commande qui travaille dans le projet, ou un enchaînement dont chaque morceau passe (`cargo build && cargo test`, `cd frontend && npm test`, `npx vitest`) → variant suffit
- Faire échouer une course pour un refus → variant suffit (PR #89, inchangé)
- Laisser le dossier temporaire d'une course après sa fin, ou le laisser dépasser sa borne sans arrêter la course → invariant (famille « bornes » : une limite configurée ; « processus » : rien ne survit)
- Changer les droits de l'agent principal (la conversation) ou de *Vibe* → variant suffit

## Où ça casse

- Que les règles de refus de Claude Code jugent bien chaque morceau d'un enchaînement (`cd x && git push`) et laissent passer le reste en mode qui ne demande jamais avec `Bash` entier permis : à mesurer avant de coder, sur le SDK installé.
  - **Mesure du 12 novembre** (SDK 0.3.285, Claude Code 2.1.285). Pas de course réelle : la Forme n'a pas `Bash` entier, son essai (`claude --version`) a été refusé en `dontAsk`. Lu dans la doc des permissions (code.claude.com/docs/en/permissions) :
    - chaque morceau est jugé : séparateurs `&&`, `||`, `;`, `|`, `|&`, `&`, saut de ligne ; un refus vaut dès qu'un morceau le touche, sous-shell, `$(…)` et corps de `for` compris ;
    - le refus l'emporte toujours (refus, puis demande, puis permis) : `Bash` entier ne passe pas sous `Bash(git push *)` ; en `dontAsk`, ce qui n'est ni permis ni refusé est refusé sans question ;
    - `Bash(git push *)` couvre aussi `git push` seul, à la frontière d'un mot (pas `git pushx`) ; `:*` en fin vaut ` *` ;
    - ôtés avant le jugement : `timeout`, `time`, `nice`, `nohup`, `stdbuf`, `command`, `builtin`, `noglob`, `xargs` sans option, les assignations de tête (`VAR=x git push` est refusé) : `timeout 60 git push` est donc refusé ;
    - pas ôtés : `bash -c`, `sh -c`, `env`, `npx`, un préfixe comme `distrobox enter dev --` : d'où les refus aussi derrière le préfixe des actions ;
    - la doc le dit : un refus couvre la forme que Claude écrit d'ordinaire, pas une frontière de sécurité.
  - Reste à vérifier sur une vraie course, au premier test de bout en bout : un `*` au milieu d'une règle (`node *vibecoder.mjs*`, pour la CLI quel que soit son chemin).
  - Trouvé en route : `distrobox` dans la liste de refus refuse toute commande derrière le préfixe `distrobox enter dev --`, tests compris.

## Ce que ça touche

- `src/main/core/vibecoder/rights.ts` : `projectCommands` et `commandRules` retirés ; la liste de refus (une constante) et ce que le skill en ouvre.
- `src/main/app/controllers/runs.ts` (`runRights`), `src/main/core/agents/options.ts` (`allowedTools` : les outils du skill plus `Bash` ; `disallowedTools` : la liste de refus moins ce que le skill ouvre ; la consigne commune allégée).
- Les skills (`resources/vibecoder/plugin/skills/*/SKILL.md`, `agents/developpeur.md`) : `allowed-tools` garde leurs outils et ne nomme plus, en commandes, que celles de la liste de refus qu'ils ouvrent.
- Tests : `rights.test.ts`, `runs.test.ts` (variants) ; le test protégé `run-rights.test.ts` (I-57), retouché pour la liste de refus.
- `SPEC.md` (F-115, « Ses droits » ; I-57), le README (le tableau des droits), `AGENTS.md` (la règle des commandes du projet retirée).

## Forme

**Huit modules.** Le code d'abord, en un seul commit : la liste de refus, le
type des droits, les options du SDK et `runRights` ne compilent qu'ensemble
(`runRules` rend `{ allow, deny }`). Puis le texte des skills. Puis le dossier
temporaire d'une course (décision du 13 novembre), du pur vers l'extérieur : le
réglage, son chemin et son environnement, la mesure d'un dossier, sa vie à côté
de la course, le ménage d'un test. Puis la doc.
Le contrôle des fichiers (`bounds.ts`) ne change pas. Le test protégé
`run-rights.test.ts` (I-57) est retouché à part, par les invariants, comme
l'invariant du dossier temporaire.
