# 0.6.0 — Ouvrir le dossier d'un agent dans l'éditeur

## Ce que ça fait

- Clic droit sur un robot : *Ouvrir dans l'éditeur (zed)* ouvre le dossier de
  l'agent dans l'éditeur de code, après *Ouvrir sur GitHub*.
- L'éditeur : la commande réglée (`editorCommand` dans `config.json`, ex.
  `zed`, `code`, `flatpak run com.visualstudio.code`), le dossier ajouté en
  dernier argument. Vide (défaut) : le premier trouvé parmi `zed`, `code`,
  `cursor`, `codium` (dans `PATH` ou `~/.local/bin`, comme `claude`).
  Pas de `$EDITOR` : c'est le plus souvent un éditeur de terminal, qui n'a pas
  de fenêtre où s'ouvrir.
- Entrée grisée (*Ouvrir dans l'éditeur*) quand aucun éditeur n'est trouvé.
- Clic droit sur l'icône → *Agents Claude Code* : *Éditeur : zed* (ou *Aucun
  éditeur trouvé*) et *Changer d'éditeur… (editorCommand)*, qui ouvre
  `config.json`, comme pour `agentCommand`.
- L'éditeur vit sa vie : détaché, il reste ouvert si l'appli quitte.

## Ce que ça ne doit pas faire

- Faire passer le dossier par un shell, ou le découper : un seul argument,
  tel quel, même avec espaces, `;`, `$(…)` ou guillemets. → invariant (I-27)
- Faire tomber l'appli quand l'éditeur est introuvable, n'est pas exécutable
  ou échoue au lancement. → invariant (I-29)
- Lire `$EDITOR`, ou du code propre à un bureau (`xdg-open`, KDE…). →
  structure (I-28)

## Ce que ça touche

- `app/menus/agent-menus.ts` : `openAgentMenu`, l'entrée après GitHub.
- `app/menus/main-menu.ts` : sous-menu *Agents Claude Code*.
- `core/config` : `editorCommand` (défaut `''`).
- SPEC F-56, § 9, I-29, S-37, § 14 ; README.

## Forme

```
main/technicals/editor/   findEditor(command) → { name, open(dir) } | null
                          EDITORS : les éditeurs cherchés, dans l'ordre
                          · ne connaît pas : Electron, les agents, la config
                          · utilisé par : app/menus
                          spawn détaché, sans shell, erreurs avalées ;
                          programme trouvé par technicals/paths (which),
                          commande découpée par helpers (splitCommand)
```

## Pistes pour plus tard

- Choisir l'éditeur dans un sous-menu (éditeurs trouvés, en boutons radio)
  plutôt que dans `config.json` : utile le jour où il y en a plusieurs.
- Windows : `code` y est un `code.cmd`, qu'on ne lance pas sans shell ;
  régler `editorCommand` sur le chemin de `Code.exe`.
- Variables de l'AppImage (`LD_LIBRARY_PATH`…) héritées par l'éditeur : sans
  effet sur Zed ; à nettoyer si un éditeur natif de l'hôte s'en plaint.
