# 0.6.0 — Ouvrir le dépôt GitHub d'un agent

## Ce que ça fait

- Clic droit sur un robot : une entrée *Ouvrir sur GitHub — propriétaire/dépôt*
  ouvre `https://github.com/propriétaire/dépôt` dans le navigateur par défaut.
  Le nom affiché est celui qui sera ouvert : on voit avant de cliquer.
- L'adresse vient du dépôt Git **du dossier de l'agent** : un `.git` dans ce
  dossier (pas dans un dossier parent), son remote `origin`, et rien d'autre.
- Entrée grisée (*Ouvrir sur GitHub*) quand on ne peut pas l'afficher : pas de
  `.git`, pas d'`origin`, ou une origine qui n'est pas sur `github.com`.
- `.git` en fichier (worktree, sous-module) : suivi jusqu'à la configuration
  du dépôt (`gitdir:`, puis `commondir`).
- Lu à chaque clic droit : un `git remote set-url` est vu au menu suivant.
- Origines reconnues : `https://github.com/o/d(.git)`, `git@github.com:o/d(.git)`,
  `ssh://git@github.com/o/d(.git)`, `git://github.com/o/d(.git)`.

## Ce que ça ne doit pas faire

- Ouvrir autre chose que `https://github.com/<propriétaire>/<dépôt>` : ni un
  autre hôte (`github.com.exemple.fr`, `exemple.fr/github.com/…`), ni un
  autre schéma (`file:`, `javascript:`), ni un chemin, une requête ou un
  fragment en plus. L'adresse est **reconstruite** à partir du propriétaire
  et du dépôt, jamais recopiée. → invariant (I-32)
- Mettre dans l'adresse ouverte les identifiants d'une origine
  (`https://utilisateur:jeton@github.com/…`) : le jeton finirait dans
  l'historique du navigateur. → invariant (I-32)
- Ouvrir un autre remote qu'`origin` (`upstream`, un fork). → invariant (I-32)
- Lancer `git` ou un shell pour lire l'origine : la configuration se lit dans
  les fichiers (I-27 ; et `git` n'est pas requis sous Windows). → structure
- Laisser l'entrée active sans `.git` ou sans origine GitHub. → variant suffit,
  vu en review (S-36)

## Ce que ça touche

- `app/menus/agent-menus.ts` : `openAgentMenu`, l'entrée après le dossier.
- SPEC F-56, I-32, S-36, § 1 (modules du principal), § 12 ; README.

## Forme

```
main/core/repo/      githubPage(dir, read) → 'https://github.com/o/d' | null
                     githubUrl(remote) → 'https://github.com/o/d' | null (pur)
                     · ne connaît pas : Electron, le disque (read injecté :
                       chemin → texte, ou null si illisible), git
                     · utilisé par : app/menus
app/menus/agent-menus.ts
                     lit avec fs, ouvre par shell.openExternal ; seul fichier
                     qui connaît Electron pour cette entrée
```

## Pistes pour plus tard

- Remonter aux dossiers parents (agent dans un sous-dossier d'un dépôt) :
  écarté, la demande est « un `.git` dans le dossier de l'agent ».
- Hôtes SSH personnalisés (`git@github-travail:o/d`, alias de `~/.ssh/config`),
  réécritures `url.<base>.insteadOf`, GitHub Enterprise, GitLab : grisés pour
  l'instant (on n'ouvre que ce qu'on sait reconnaître sans ambiguïté).
- Ouvrir la branche courante (`/tree/<branche>`).
