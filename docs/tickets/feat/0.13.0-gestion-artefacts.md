# 0.13.0 — Gérer les artefacts comme des fichiers

## Ce que ça fait

- La liste du panneau *Artefacts* devient une arborescence de fichiers, comme
  l'explorateur de VS Code : l'utilisateur range lui-même les artefacts du
  projet.
- Les dossiers se plient et se déplient ; *Tout replier* les referme tous.
- Un clic droit sur un artefact ou un dossier ouvre un menu contextuel :
  *Renommer*, *Supprimer*, *Copier*, *Couper*, *Coller*, *Dupliquer*. Un clic
  droit sur la zone de la liste, ou sur un dossier : *Nouveau fichier*,
  *Nouveau dossier* (dans un dossier, un sous-dossier).
- Raccourcis clavier : F2 renomme, Suppr supprime, les flèches parcourent
  l'arborescence, Échap annule un renommage.
- *Renommer* : le nom devient un petit champ de texte, sur place, dans la
  liste. Entrée valide et l'élément prend ce nom. Un nom impossible (déjà pris,
  vide, avec un séparateur…) : l'encart passe en rouge, avec un court message
  qui dit pourquoi. Même champ pour nommer un nouveau fichier ou un nouveau
  dossier.
- *Supprimer* demande confirmation dans une petite boîte dessinée dans le
  panneau ; ce qui est supprimé part dans la corbeille du système, récupérable.
- Un dossier se renomme, se déplace et se supprime avec tout son contenu, comme
  un fichier.
- Un artefact ou un dossier se déplace dans un dossier par glisser-déposer.
- Déplacer, coller ou dupliquer là où le nom est déjà pris : le nouveau prend
  le premier numéro libre avant son extension (`rapport-2.md`), comme au dépôt.
- Ctrl et Maj sélectionnent plusieurs éléments à la fois. Une sélection se
  supprime (une confirmation pour tout), se déplace, se copie, se coupe et se
  copie dans le projet (*Copier dans le projet*). Plusieurs éléments
  sélectionnés : le centre reste vide.
- L'arborescence est elle-même la zone de dépôt, comme dans VS Code : un fichier
  ou un dossier glissé depuis le gestionnaire de fichiers est copié dans le
  dossier où on le lâche, à la racine hors de tout dossier. La zone de dépôt
  séparée disparaît, et le bouton *Ajouter* avec elle (le dépôt et *Nouveau
  fichier* suffisent).
- Le dossier d'arrivée d'un dépôt passe par `conv:vibeDrop`, désigné par son id
  du dernier relevé, jamais par un chemin : le pont devient `vibeDrop(files,
  dossier)` (modification de `src/preload/panel.ts` acceptée par
  l'utilisateur). Un id absent ou inconnu : la racine.
- Le nom tapé (renommer, nouveau fichier, nouveau dossier) passe par
  `conv:vibeRun`, en argument d'une action directe, sans nouveau canal : un nom
  seul, jamais un chemin, que le principal revérifie ; l'élément visé est
  désigné par son id du dernier relevé (moins de surface qu'un canal de plus,
  et `src/preload/` reste intact).

## Ce que ça ne doit pas faire

- Renommer, créer, déplacer, coller, déposer ou supprimer hors du dossier
  d'artefacts du projet, un nom en `..`, absolu, avec un séparateur ou un NUL
  compris, un id de dossier en forme de chemin aussi (I-37, I-39) → invariant
- Effacer définitivement : une suppression passe toujours par la corbeille du
  système → invariant
- Suivre un lien, ni un lien sous le dossier, ni un dossier qui serait un lien
  (I-37) → invariant
- Écraser un artefact existant en renommant, déplaçant, collant ou dupliquant
  (comme au dépôt et au transfert, `COPYFILE_EXCL`) → invariant
- Supprimer un autre élément que ceux confirmés : les ids `a<i>` glissent quand
  la liste change (`artifacts-view.tsx`), un robot peut écrire entre le relevé
  et le clic → invariant
- Supprimer sans confirmation → vu en review
- Joindre à la conversation, ou recopier par `conv:vibeDrop`, un artefact
  glissé dans l'arborescence (`panel-app.tsx` reçoit tout dépôt sur
  `document`) → vu en review
- Joindre à la conversation un fichier extérieur lâché sur l'arborescence
  → vu en review
- Déplacer un dossier dans lui-même ou dans un de ses sous-dossiers
  → variant suffit
- Perdre l'artefact affiché au centre quand on le renomme ou le déplace (le
  choix est tenu par le nom, `artifacts-view.tsx`) → variant suffit
- Montrer les dossiers cachés (F-95) → variant suffit
- Ajouter un canal pour le nom tapé (il passe par `conv:vibeRun`) → structure

## Où ça casse

- Le relevé s'arrête à 1 000 fichiers (`LIST_MAX`,
  `src/main/app/controllers/artifacts.ts`) : l'arborescence n'en montre pas
  plus.

## Forme

**Les dossiers dans le relevé.** Un dossier est désigné par `d<i>` (ordre des noms),
comme un fichier par `a<i>` : la page n'envoie que ces ids, jamais un chemin ; un
id inconnu ou en forme de chemin ne trouve rien. Côté page, l'arborescence tient ses
nœuds par leur nom (le chemin sous le dossier d'artefacts), stable d'un relevé à
l'autre : pliage, sélection et presse-papiers survivent au glissement des ids, qui ne
sont lus qu'au moment d'agir. **Supprimer** envoie, avec les ids, les noms
confirmés : le principal compare chaque nom à celui de l'id dans son dernier relevé
et refuse tout (rien en corbeille) au premier écart ; ces noms ne sont jamais lus
comme des chemins. **Déplacer, renommer : copie puis effacement**, comme
`moveContents`, jamais `rename` (qui écrase un fichier sur Linux). **Les règles
d'un nom** sont écrites deux fois : `nameProblem` (la page, pour l'encart rouge) et
`plainName` (le principal, qui décide) ; quelques lignes en double plutôt qu'un
module partagé hors des ponts.
