# 0.13.0 — Le panneau Artifacts

## Ce que ça fait

- Un bouton dans l'en-tête de VibeCoder, *Artefacts* en français,
  *Artifacts* en anglais, à côté de *Créer* / *Relire* mais séparé d'eux
  (F-92) : c'est un autre contexte, ni le parcours de *Créer* ni celui de
  *Relire*.
- Un clic ouvre le panneau : à gauche, la liste de tous les artefacts de
  l'agent ; au centre, le contenu de celui qu'on choisit dans la liste.
- Les artefacts sont rangés dans les sorties de l'agent,
  `vibecoder-out/<agent>/artifacts/` : un agent, ses artefacts, les mêmes
  pour toutes ses branches (comme son dossier de sorties).
- Tout ce que Chromium sait afficher est rendu tel quel. Une page HTML (un
  wireframe) est rendue dans un bac à sable, sans script ni réseau (un
  wireframe est du HTML et du CSS statiques ; un script de l'agent n'a pas
  à tourner à côté du pont du panneau). Un fichier que Chromium ne sait pas
  afficher (un binaire) s'affiche quand même, en texte, comme dans un
  éditeur classique (VS Code) : illisible, mais montré.
- Au-delà d'une limite configurée (10 Mo par défaut), le texte affiché est
  coupé, avec « fichier tronqué » ; *Ouvrir dans l'éditeur* montre la suite.
  Les médias rendus par Chromium ne sont pas coupés.
- Un artefact affiché s'ouvre dans l'éditeur, ou se copie dans le projet :
  l'utilisateur choisit le dossier dans une boîte de dialogue, où il veut,
  dans le dossier de l'agent ou ailleurs ; un fichier du même nom existe
  déjà → l'appli demande s'il faut le remplacer.
- La conversation reste dans la colonne de droite : on demande à l'agent de
  retoucher l'artefact affiché.
- Les artefacts servent VibeCoder : quand l'utilisateur demande à l'agent un
  document qui sort du projet, l'agent le crée en artefact, par un skill
  dédié qu'il prend seul (pas de bouton ni de lien : ce que l'IA fait seule
  n'a pas de bouton, F-93 ; il se trouve aussi par « / » dans le champ).
- Le but : reprendre les artefacts de Claude Desktop, pour produire des
  documents PDF, des présentations, des wireframes, des documents externes,
  des fichiers de conception… qui ne sont pas (encore) dans le projet :
  preuve de concept ou autre.

## Ce que ça ne doit pas faire

- Mêler *Artefacts* au parcours de *Créer* ou de *Relire* (un autre
  contexte, un bouton à part) → vu en review
- Lire, pour l'afficher ou l'ouvrir, un fichier hors de
  `vibecoder-out/<agent>/artifacts/`, ou désigné par un chemin venu de la
  page plutôt que par son id dans la liste (I-37, étendu à `artifacts/`)
  → invariant
- Exécuter un script d'un artefact, ou le laisser joindre le réseau
  → invariant
- Copier un artefact autrement qu'au clic de son bouton, ou ailleurs que
  dans le dossier choisi dans la boîte de dialogue (I-39 : le principal ne
  modifie le dépôt qu'au clic) → invariant
- Remplacer un fichier existant sans que l'utilisateur l'ait accepté
  → invariant
- Charger en entier, pour l'afficher en texte, un fichier au-delà de la
  limite configurée → variant suffit (le test tourne avec une petite
  limite, §3.3)
- Refuser d'afficher un fichier que Chromium ne sait pas rendre : il
  s'affiche en texte → variant suffit

## Forme

**Pas de canal nouveau.** La liste des artefacts arrive au relevé
(`VibeView.artifacts`, `shared/bridge/types.ts`, non protégé) ; le texte d'un
artefact suit le chemin de *Voir le code* (`conv:vibeFollow` → `conv:vibeCode`,
relu à chaque écriture de l'agent : la retouche demandée dans la conversation
s'affiche d'elle-même) ; *Ouvrir dans l'éditeur* passe par `conv:vibeOpen` ;
*Copier dans le projet* est une action directe (`conv:vibeRun`, `copy-artifact`,
F-114). La page ne donne jamais qu'un id `a<i>` du dernier relevé (I-37).
Inchangés : `src/preload/` et `shared/bridge/channels.ts`.

**Ce que Chromium rend : un schéma de l'appli.** Une image, un PDF, un son, une
vidéo, une page HTML ou un SVG s'affichent dans une `<iframe>` dont la source
est `vibe-artifact://<agent>/a<i>`, servie par le principal (le fichier en
flux, jamais coupé). Le principal ne sert que l'id d'un artefact du dernier
relevé de l'agent affiché, sous `artifacts/` (safePath) ; une page HTML ou un
SVG part avec l'en-tête `Content-Security-Policy: sandbox; default-src 'none';
style-src 'unsafe-inline'; img-src data:; font-src data:` (ni script, ni
réseau) et dans une `<iframe sandbox>` ; la page du panneau ajoute
`frame-src vibe-artifact:` à sa CSP (rien d'autre ne s'y charge, et le cadre
ne navigue pas ailleurs). Un wireframe tient donc en un fichier (CSS en
ligne, images en `data:`) : c'est ce que demande le skill.

**Le reste est du texte.** Markdown → `markdown-view` ; tout autre fichier, un
binaire compris → `code-view`, en lecture seule, décodé en UTF-8 comme le
ferait un éditeur. Lu jusqu'à `artifactTextMax` (10 Mo, `config.json`), pas
au-delà : « fichier tronqué ».
