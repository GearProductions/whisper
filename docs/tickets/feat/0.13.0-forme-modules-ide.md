# 0.13.0 — Une branche créée en local se gère dans VibeCoder, Forme et Modules en vue IDE

## Ce que ça fait

- Une branche créée hors du parcours (demandée à l'agent, ou en local avec
  git) se gère dans VibeCoder, même pour une petite PR sans note, sans forme
  ni invariants. Aujourd'hui on y est bloqué : seule l'étape en cours
  s'ouvre, et sans note c'est toujours la Note.
- Créateur : chaque étape du fil d'Ariane s'ouvre au clic (ou Ctrl+1…6),
  faite, en cours ou à venir, comme pour le relecteur. Le fil garde ses
  états (faite, en cours, à venir) et l'étape en cours reste la première
  qui n'est pas faite (sans note : la Note, mais on va librement aux autres).
- Seuls les boutons restent grisés : ceux dont l'action a besoin qu'une
  étape précédente soit faite, avec leur raison au survol.
- Forme et Modules deviennent à peu près la même vue, à la manière d'un IDE
  (purement de l'affichage, aucune action nouvelle) :
  - à gauche, une arborescence (TreeView) des fichiers, par dossier ;
  - à droite, le fichier choisi.
- Forme, en vue IDE (la seule vue de la Forme) :
  - l'arborescence montre les modules de la Forme ;
  - un clic sur un fichier montre sa structure en texte, comme aujourd'hui
    (son contrat : ce qu'il expose, ne connaît pas, utilisé par) ;
  - un interrupteur *Structure / Code* montre son code en diff : tout en
    vert pour un nouveau module, seulement ce que la branche a ajouté ou
    changé pour un module existant.
- Modules : un interrupteur entre la vue IDE et la vue actuelle (liste en
  accordéon, inchangée). La vue choisie est retenue d'une ouverture à
  l'autre (un réglage).
  - en vue IDE, l'arborescence montre les fichiers des modules, rangés par
    dossier (un module de plusieurs fichiers n'y fait pas un nœud), chaque
    fichier avec son point d'état (généré, en cours de génération, pas
    encore) ;
  - un clic sur un fichier montre son code en diff git ; le choix *Fichier*
    ou *diff* (en ligne, côte à côte) reste, comme dans *Voir le code*.
- Sans Forme dans la note (ou sans note), l'arborescence montre les
  fichiers que change la branche : la vue code suffit à suivre une petite PR
  qui n'a pas fait toutes les étapes.

## Ce que ça ne doit pas faire

- Ouvrir une étape à venir ne lance aucune action et n'écrit rien. → vu en review
- Une action qui a besoin d'une étape précédente faite n'est pas proposée
  active : son bouton est grisé, avec sa raison. → variant suffit
- La vue IDE n'ajoute aucune action : elle montre ce que Forme et Modules
  montrent déjà. → vu en review
- Le code s'affiche en texte, jamais en HTML (I-40). → invariant (existant)

## Pistes pour plus tard

- Lire l'état des étapes dans git plutôt que dans des fichiers internes
  (validations, sorties, courses) : retiré pour simplifier, la vue code
  couvre le besoin d'une branche sans étapes.

## Forme

**Toutes les étapes s'ouvrent, dans les deux rôles.** `VibeStep.open` n'a plus
de raison d'être : il est retiré (le principal ne le calcule plus, le fil
d'Ariane et Ctrl+1…6 ne le lisent plus). L'étape en cours reste la première
pas faite. Une action dont la raison est `noNoteYet` (la Forme, les
invariants, un gabarit qui lit la note) n'est plus masquée mais grisée, sa
raison au survol ; les autres raisons de `notYet` restent masquées (elles ne
disent pas qu'une étape précédente manque).

**Les fichiers de la branche, par id.** Sans Forme, l'arborescence montre ce
que change la branche (`repo.changed`, la copie de travail comprise) : le
relevé les donne (`VibeView.files`, ids `b<i>`), et `codeFile` traduit `b<i>`
comme `m<rang>/<i>` — jamais un chemin venu de la page (I-37). Lus dans les
deux rôles ; `saveCode` refuse toujours le relecteur, et un fichier `b<i>` est
grisé comme la note (toute course retient).

**La vue IDE réutilise le code qu'on a.** À droite, `ModuleCode` tel quel (le
sélecteur Fichier / diff, En ligne / Côte à côte, l'éditeur), avec deux
réglages de plus : sans sa rangée de fichiers (l'arborescence la remplace) et
le diff depuis la base affiché d'abord (Forme, *Code*). Un fichier de la
branche hors module y passe comme un module d'un seul fichier, construit par
`ide-files`. Les outils restent ceux d'aujourd'hui, au-dessus du fichier
choisi : citer, commenter, ouvrir (Forme) ; Générer, Relire le diff, Ouvrir,
Commiter de son module (Modules). Point d'état d'un fichier : celui de son
module (`commité` = généré, `en cours`, `à faire` = pas encore).
