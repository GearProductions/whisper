# 0.10.0 — Familles d'agents : un dépôt, ses worktrees

## Ce que ça fait

- L'appli regroupe en **famille** les agents d'un même dépôt git, reconnus
  d'eux-mêmes par le même `git rev-parse --git-common-dir` (résolu), sans rien
  à déclarer. Le **parent** est l'agent du dossier principal ; chaque worktree
  a son **robot enfant**.
- Les robots enfants s'affichent **sous** le robot de leur parent, plus
  petits, de sa couleur, avec une pastille : la branche du worktree, ou
  « PR #n ».
- Un enfant est un agent ordinaire (conversation, éditeur, VibeCoder ; un
  agent = un dossier, F-51). Il porte un `parent` **durable** dans
  `config.json`, qui remplace `temp` (F-110, § 9) : il survit au redémarrage
  de l'appli.
- Le clic droit du parent gagne un sous-menu *Worktrees* : les worktrees du
  dépôt (`git worktree list`) qui n'ont pas d'agent, chacun avec *Ouvrir un
  agent ici*. Un dossier jamais choisi passe par la question de confiance
  (I-23, I-31).
- Un enfant reprend les commandes du projet de son parent (fichier du
  projet, F-111) et les lance dans **son** dossier (`cwd` relatif à ce
  dossier).
- Dans une famille, une même commande ne tourne qu'à un endroit à la fois
  (les ports et la base sont partagés). La lancer ailleurs demande :
  « <nom> tourne dans <branche> : l'arrêter et le lancer ici ? ».

## Ce que ça ne doit pas faire

- Créer un agent enfant sur un dossier qui n'est pas la racine d'un worktree
  du même dépôt, ou sans la question de confiance acceptée. → invariant
  (I-41 réécrit : un enfant naît aussi d'*Ouvrir un agent ici* ; son test
  protégé se réécrit, accord donné ; I-23)
- Lancer deux fois la même commande du projet dans une même famille.
  → invariant
- Perdre un robot de PR enregistré à l'ancien format : `temp` se lit comme
  `parent`. → variant suffit
- Créer ou retirer un worktree : hors de ce ticket (recette de projet,
  worktrees en *Relire* et *Créer*). → vu en review

## Où ça casse

- Un processus Claude Code par enfant utilisé (quelques centaines de Mo
  chacun, § 14).

## Forme

Une famille se **reconnaît** par git (`--git-common-dir` et `--show-toplevel`
résolus, comme le robot de PR aujourd'hui) et se **retient** dans
`config.json` : `agents[].parent` `{ id, pr? }` (la forme de `temp`, qui se lit
pareil). L'affichage, le menu et la règle des commandes ne lisent que ce
`parent` enregistré (synchrone) ; git ne sert qu'à l'écrire : au lancement,
à la création d'un agent, à *Ouvrir un agent ici*. Un `parent` dont l'agent
manque : un robot ordinaire, `parent` gardé. Le robot de PR (F-110) est un
enfant avec `pr` : il part toujours avec sa fiche ; un enfant sans `pr` ne
part qu'à *Retirer*.
