# 0.13.0 — L'étape Modules plus simple : ordre des modules, boutons sur leur ligne, relecture automatique, affichage du code retenu

## Ce que ça fait

- Chaque module de la Forme porte un numéro : son rang dans la Forme, qui
  est l'ordre où le générer et le commiter (fonctions pures → orchestration
  → composants → colle ; un module attend ceux qu'il utilise).
- Modules, vue liste : le numéro devant le nom, « Ordre de génération : n
  sur N » au survol.
- Vue IDE (Forme et Modules) : le numéro devant le nom de chaque fichier de
  l'arborescence, celui de son module (le même pour tous les fichiers d'un
  module).
- Sans Forme, les fichiers de la branche n'ont pas de numéro.
- Vue IDE (Forme et Modules) : à droite, seul le code défile. Les boutons du
  module (*Générer*, *Relire le diff*, *Ouvrir*) et le choix *Fichier* /
  diff restent en place au-dessus, les outils du code dessous. Sans code (la
  structure d'un module de la Forme), toute la colonne défile, comme avant.

- *Générer ce module* et *Commiter ce module* quittent l'en-tête de l'étape
  (trop de boutons) : chaque module a les siens sur sa ligne.
  - Liste : *Générer* et *Commiter* toujours au bout de la ligne, à droite
    du nom, replié comme déplié ; déplié, suivis de *Relire le diff* et
    *Ouvrir*.
  - Vue IDE : *Générer*, *Commiter*, *Relire le diff*, *Ouvrir*, sur la même
    ligne que le choix *Fichier* / diff.
  - *Commiter* n'apparaît que pour un module qui a des changements pas
    commités (généré, pas encore commité).
  - Quand générer est la prochaine action, le *Générer* du premier module
    pas touché est mis en avant (ce que *Générer ce module* aurait pris).

- L'affichage du code d'un module (*Fichier*, *Diff depuis la base de la
  branche*, *Diff depuis le dernier commit* ; *En ligne* · *Côte à côte*) :
  - par défaut, le diff depuis la base de la branche (le fichier quand ce
    diff est grisé) ;
  - le choix est le même pour tous les fichiers : changer de fichier, puis
    revenir, le garde ; tant que la page vit, pas enregistré.

- L'en-tête de l'étape Modules ne montre que ce qui a un sens :
  - *Préparer le commit* : seulement s'il y a quelque chose à commiter ;
  - *✓ Valider → commit → suivant* : seulement s'il y a un module pas
    commité et un suivant à générer ;
  - *Générer les modules restants* : seulement s'il reste un module pas
    touché (il restait toujours actif).
- Les actions de l'étape (*Valider → commit → suivant*, *Préparer le
  commit*, *Générer les modules restants*, *Commiter les modules*) passent
  dans la carte des modules, à côté de son titre : l'en-tête de l'étape ne
  garde que *Vibe*. Sans module dans la Forme, elles restent dans l'en-tête.
- Dans toutes les étapes, les actions de l'en-tête sont sur la ligne du
  titre (*Vibe* à côté de « Modules »), plus sur une ligne à part.
- Moins de place perdue : marges de l'étape, de la vue IDE et de la poignée
  réduites.
- *Relire le diff* n'est plus un choix : il part seul après *Générer* (ce
  module), dans une seconde course, par un autre agent que celui qui a
  écrit, comme *Lancer les vérifications* demande la ponytail review. Il
  quitte l'en-tête ; *Relancer* reste sur sa carte, et *Relire le diff* sur
  la ligne d'un module déplié (après une retouche à la main).
  - Pas de relecture demandée si la génération s'arrête sans écrire le
    module, ni pour *Générer les modules restants* (il relit déjà chaque
    diff).

- Vue IDE (Forme et Modules) : le point d'état disparaît de l'arborescence.
  Il disait l'état du module, pas du fichier (un fichier commité au premier
  commit, puis modifié par la génération, restait vert). Le nom de chaque
  fichier est coloré comme dans VS Code, d'après `git status` :
  - vert : nouveau, pas commité ;
  - jaune : modifié, pas commité ;
  - rouge barré : supprimé, pas commité ;
  - couleur ordinaire : commité ;
  - atténué en italique : module pas encore généré.
  Dans la Forme, un module d'un seul fichier prend sa couleur ; un dossier
  est jaune si l'un de ses fichiers n'est pas commité. La vue liste garde
  ses points (l'état du module).

## Ce que ça ne doit pas faire

- Le numéro ne change rien à ce que font *Générer*, *Générer les modules
  restants*, *Commiter les modules* : il ne fait que montrer l'ordre de la
  Forme qu'ils suivent déjà. → vu en review
- Pas de numéro sur un dossier. → variant suffit
- Le défilement ne change que la mise en page : aucun bouton ni contenu en
  plus ou en moins. → vu en review
- Déplacer les boutons n'ajoute aucune action : *Générer* et *Commiter* d'un
  module lancent ce que lançaient ceux de l'accordéon déplié. → variant suffit
- La relecture automatique ne modifie ni ne commite rien : elle écrit
  `review.md`, comme le bouton. → vu en review

## Ce que ça touche

- `src/renderer/app/panel/vibecoder/file-tree-view.tsx` : `rank`, le numéro
  d'un fichier.
- `src/renderer/app/panel/vibecoder/ide-view.tsx` : `rank` + 1 de chaque
  fichier (`IdeFile.rank`, déjà calculé par `ideFiles`) ; `ide-view.css` :
  la colonne de droite, dont seul le code défile.
- `src/renderer/app/panel/vibecoder/modules-view.tsx`, `modules-view.css` :
  le numéro dans la liste ; les boutons de chaque module sur sa ligne, hors
  de l'en-tête de l'étape.
- `src/renderer/app/panel/vibecoder/module-code.tsx` : `tools`, en tête de la
  rangée du sélecteur ; le choix d'affichage commun, le diff depuis la base
  d'abord (`first` disparaît ; `forme-view.tsx` ne le passe plus).
- `src/main/technicals/git` : `added`, les fichiers nouveaux du `git status`.
- `src/shared/bridge/types.ts` : `VibeGit`, `git` sur les fichiers d'un
  module et de la branche.
- `src/renderer/core/vibecoder/ide-files.ts` : `mark`, la couleur d'un
  fichier.
- `src/main/core/vibecoder/journey.ts` : `git` de chaque fichier ; masquer *Préparer le commit*,
  *Valider → commit → suivant* et *Générer les modules restants* quand ils
  n'ont rien à faire.
- `resources/vibecoder/plugin/skills/module/SKILL.md` (demander la
  relecture), `modules/SKILL.md` (pas pour ses sous-agents),
  `actions.fr.json`, `actions.en.json` (l'aide de *Générer ce module*).
- `SPEC.md`, `README.md`.
