# 0.13.0 — Recharger l'interface, redémarrer, en mode dev

## Ce que ça fait

En mode dev (`whisper-dev`, l'appli lancée depuis les sources), on itère sans
attendre une release, et sans arrêter les agents quand seules les pages
changent :

- `whisper-dev` reconstruit en continu, dans la box, les pages
  (`vite build --watch`) et le principal avec ses ponts (`vite build -c
  vite.main.config.mts --watch`), tant qu'une appli dev tourne (y compris
  après un redémarrage).
- L'appli compare toutes les 2 s ce qui est construit dans `out/` à ce
  qu'elle a chargé, par empreinte du contenu (une reconstruction à
  l'identique ne compte pas) :
  - **les pages seules ont changé** : un bouton **Recharger l'interface**,
    dans l'en-tête de VibeCoder, à droite, à côté de FR / EN, recharge les
    fenêtres ; le principal et les agents continuent ;
  - **le principal (ou un pont) a changé** : à la place, **Redémarrer**, avec
    une pastille. Les pages neuves ne marcheraient pas avec l'ancien
    principal : *Recharger* n'est plus proposé. Un clic relance l'appli ; si
    un agent travaille (un tour, une course), sur n'importe quel agent, la
    question d'abord : « Des agents tournent : voulez-vous quand même
    redémarrer ? » Oui / Non ;
  - **rien n'a changé** : aucun bouton.
- Au clic, `out/` est relu à l'instant : *Recharger* ne part pas si le
  principal vient d'être reconstruit, ni pendant une dictée (le micro est
  dans une page) ; *Redémarrer* ne relance pas tant que `out/main` est en
  cours de construction ; un second clic n'empile pas une seconde question.
- Dans la version publiée, rien de tout cela.

## Ce que ça ne doit pas faire

- Apparaître ou agir dans la version publiée (l'appli empaquetée). → variant
  suffit (le principal refuse aussi : `app/dev` ne démarre pas)
- Recharger les pages quand le principal a été reconstruit (des pages neuves
  face à un ancien principal). → variant suffit
- Redémarrer sans la question quand un agent travaille. → variant suffit
- Arrêter un agent ou interrompre un tour en rechargeant l'interface. → vu en
  review
- Ouvrir un canal nouveau entre les pages et le principal (`src/preload/`,
  `channels.ts` inchangés : `conv:vibeSet`). → vu en review

## Ce que ça touche

- `src/main/helpers/build-state.ts` (nouveau) : redémarrer, recharger, rien.
- `src/main/app/dev/` (nouveau) : l'empreinte de `out/`, relue toutes les
  2 s ; recharger les fenêtres ; relancer l'appli.
- `src/main/app/lifecycle.ts` : `startDev` au lancement.
- `src/shared/bridge/types.ts` : `VibeView.dev`, `VibePatch.reloadUi`,
  `VibePatch.restartApp`.
- `src/main/app/controllers/vibecoder.ts` : `dev` au relevé ; recharger,
  redémarrer (la question si des agents travaillent).
- `src/renderer/app/panel/vibecoder/vibe-coder.tsx`, `core/vibecoder` (i18n),
  `vibecoder.css` : le bouton.
- `~/dev/Gear/tools/whisper.sh` (hors du dépôt) : les constructions
  continues.
- `README.md` (le mode dev).

## Forme

```
main/helpers/build-state.ts buildState(loaded: Builds, built: Builds) →
                            'restart' | 'reload' | null ; Builds = { main,
                            pages : string | null } (empreintes ; null : pas
                            construit, rien à dire)
main/app/dev/               startDev(onChange) : hors empaquetée, l'empreinte
                            de out/main/*.js et out/renderer/**.html au
                            lancement, relue toutes les 2 s ; devState() ;
                            reloadPages() : chaque fenêtre rechargée, les
                            pages chargées à jour ; restartApp() :
                            app.relaunch puis app.quit
main/app/lifecycle.ts       startDev(() => refreshVibe({ now: true }))
shared/bridge/types.ts      VibeView.dev?: 'reload' | 'restart' | null ;
                            VibePatch.reloadUi?: true ; restartApp?: true
main/app/controllers/vibecoder.ts  survey : dev = devState() ; setVibe :
                            reloadUi si 'reload' → reloadPages ; restartApp si
                            'restart' → un agent au travail (isBusy, une course
                            qui retient) : la question, Oui → restartApp
renderer/app/panel/vibecoder/vibe-coder.tsx  'reload' : Recharger
                            l'interface ; 'restart' : Redémarrer et sa
                            pastille ; à côté de FR / EN
renderer/core/vibecoder/i18n.ts  leurs libellés (fr, en)
```
